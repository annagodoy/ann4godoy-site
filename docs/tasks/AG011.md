# AG011 — Repositório público e integração contínua

## Objetivo

Publicar o projeto em um repositório público no GitHub e executar automaticamente a quality gate em pushes e pull requests.

**Status:** concluída.

## Problema

O projeto possui checagem de tipos e build reproduzíveis localmente, mas o repositório ainda não possui remote nem validação hospedada. Atualizações de código ou conteúdo podem ser enviadas sem que essas etapas sejam executadas.

## Decisão técnica

- Publicar `ann4godoy-site` como repositório público no GitHub.
- Usar `ann4godoy` e o e-mail `noreply` da conta como identidade Git.
- Criar o repositório remoto sem arquivos iniciais para preservar o histórico local.
- Usar GitHub Actions como provedor de CI.
- Executar `npm ci`, `npm run check` e `npm run build` em pushes e pull requests para `main`.
- Usar Node.js 22, coerente com o campo `engines` do projeto.
- Não realizar deploy automático nesta tarefa.

Referência:

- [GitHub — Building and testing Node.js](https://docs.github.com/actions/tutorials/build-and-test-code/nodejs)

## Fora do escopo

- deploy ou hospedagem do site;
- domínio customizado;
- secrets de produção;
- testes unitários ou end-to-end;
- Dependabot;
- proteção de branch obrigatória;
- publicação de pacotes npm.

## Critérios de aceite

- [x] O repositório está público no GitHub sem segredos expostos.
- [x] O histórico utiliza a identidade `noreply` definida.
- [x] `origin` e upstream de `main` estão configurados.

- [x] O workflow usa instalação reproduzível pelo lockfile.
- [x] A execução inicial da CI termina com sucesso.
- [x] O README diferencia CI de deploy.
