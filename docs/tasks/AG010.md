# AG010 — Validação estática e quality gate local

## Objetivo

Adicionar uma checagem explícita de tipos para componentes Astro, TypeScript e React, criando uma quality gate local reutilizável por uma futura integração contínua.

**Status:** concluída.

## Problema

O comando `astro build` gera o site e valida as coleções, mas não executa a checagem completa de tipos do projeto. Atualmente, parte dos erros pode aparecer no editor sem interromper a validação executada antes de um commit.

O repositório ainda não possui remote configurado. Portanto, uma CI hospedada seria inativa neste momento. A validação deve primeiro existir como comando local e depois ser reutilizada pelo provedor de CI.

## Decisão técnica

- Instalar `@astrojs/check` e `typescript` como dependências de desenvolvimento.
- Criar um script `npm run check` separado do script de build.
- Manter `npm run build` responsável somente pela geração do site.
- Tratar `check` e `build` como duas validações obrigatórias antes de commits de produto.
- Adiar GitHub Actions até existir um remote e um repositório hospedado.

Referências:

- [Astro — Type checking](https://docs.astro.build/en/guides/typescript/#type-checking)
- [GitHub — Building and testing Node.js](https://docs.github.com/actions/tutorials/build-and-test-code/nodejs)

## Fora do escopo

- GitHub Actions ou outro provedor de CI;
- publicação do repositório;
- deploy automático;
- testes unitários ou end-to-end;
- linting ou formatação automática;
- mudanças funcionais na aplicação.

## Critérios de aceite

- [x] `@astrojs/check` e `typescript` estão em `devDependencies`.
- [x] `npm run check` verifica o projeto completo.
- [x] Checagem e build terminam sem erros.
- [x] O README diferencia os dois comandos.
- [x] O fluxo pode ser reutilizado futuramente por uma CI.

## Objetivos de estudo

- diferença entre transpilação e checagem de tipos;
- scripts npm como interface de automação;
- dependências de produção e desenvolvimento;
- quality gates locais;
- preparação incremental para CI.

## Paralelos com Rails

| Ecossistema Astro | Paralelo em Rails |
| --- | --- |
| `astro check` | Verificação estática como RuboCop ou Sorbet |
| `astro build` | Compilação de assets e preparação da aplicação |
| Script npm | Task Rake ou comando padronizado do projeto |
| Quality gate local | Sequência de checks executada antes do push |

## Definição de pronto

A AG010 estará concluída quando o projeto possuir um comando local explícito de checagem de tipos, documentado e aprovado junto ao build, pronto para ser executado futuramente por uma CI.
